# Ventus

Ventus (internal id `runner`) runs today's timed routines step by step: press Start and it shows only what to do now, counts down, names each move and its reps, rests between rounds, and moves on by itself. Writing steps are typed into it and kept as a journal. Each finished step ticks the same `schedule.check` record Aqua uses, so Aqua on every device updates on its own. It was designed and built on 2026-11-19; it was briefly called Usanza, then Adesso.

It exists twice: on the Mac (`KairosApp.swift`, `KairosModel.swift`, ⌥2) and as the web app at `/Pocket/ventus/` (`web/ventus/`). Both read the same routines and write the same records.

Related: [schedule.md](schedule.md) (Aqua, where routines live and are edited), [../cloud-sync.md](../cloud-sync.md) (record kinds), [../web-pages.md](../web-pages.md) (the web app), [../theme.md](../theme.md) (app colours; Ventus defaults to Flint).

## Where the routine details live

Code holds only templates; every number lives in the database (Pranav, 2026-11-19), so changing a workout is a data change, never a code change. Each Aqua step may carry a `run` object next to `title` and `tip`, in the weekly `plan` and in `dated` lists alike:

| `type` | Fields | What Ventus does |
| --- | --- | --- |
| `tap` | none | Shows the step; Done moves on |
| `timed` | `seconds`, `cues[{at, text}]`, `quiet`, `reads`, `pick`, `every` | One countdown; the cue whose `at` (seconds in) has passed is shown as "Now"; `quiet` skips the chime at the end (body scan). `reads` is a pool of lines to read if picturing is hard: today's `pick` of them show one at a time, each for `every` seconds (default 20) |
| `box` | `seconds`, `pattern` (`[in, hold, out, hold]`, default 4-4-4-4), `cues` | Box breathing: a ball travels round a square (up on in, across on hold, down on out, back on hold) with the phase and its count in the middle |
| `moves` | `moves[{name, reps \| seconds, detail}]`, `seconds` (estimate) | One beat per move: `seconds` counts down, `reps` waits for Done |
| `intervals` | `rounds`, `on`, `off`, `names` (rotate), `unit`, `onLabel`, `offName` | Work and rest countdowns; the background turns warm on work and blue on rest |
| `rounds` | `rounds`, `unit` (`round` or `set`), `rest`, `moves` | Every move in order, then a rest that names the next round's first move |
| `log` | `plan`, `seconds` (estimate) | A data-entry screen: the plan, then time, distance and notes. Nothing is tracked (Pranav's call) |
| `say` | `lines`, `pool`, `pick`, `times`, `seconds` | One line at a time, "Said it" `times` times each. `lines` always show; `pool` adds today's `pick` of its lines |

Daily picks: a pool rotates by day, starting at `(dayNumber × pick) mod pool size` and taking `pick` lines in order (`dayNumber` is days since 1970-01-01 for the session's `yyyy-MM-dd`), so every line comes round before any repeats. `KairosPlan.pick` and `pick` in `plan.js` must stay identical.
| `write` | `fields` (lines; 0 or 1 means a paragraph), `tag`, `prompt`, `seconds` (a guide only) | Text saved to the journal as you type |

A step with no `run` uses "N min" in its title as a timer, otherwise it is a tap step. Only routines with at least one guided step (any type but `tap`) appear, so Hair care never does.

The Mac keeps `run` as loose JSON (`Loose` in `ScheduleModel.swift`), so it round-trips untouched through `schedule.json` and sync; the Aqua editor never changes it. A Mac build without `Loose` would strip `run` and push the routine back without it, so the Mac update must ship before `run` data is written.

The current data was generated by `run_for(title)` in `/mnt/project-files/kairos/runs.py` from the step titles and written with SQL. To change a workout, edit the routine's `run` objects in the `schedule.routine` record (or `schedule.json` on the Mac) and let sync carry it.

## Journal

- Record kind `runner.entry`, id `routine|day|slot|step` (the same shape as a check id). Data: `{id, routine, routineName, day, slot, step, title, tag, lines?, text?, seconds?, km?, notes?, feel?, updated}`.
- Manual entries: id `manual|<uuid>`, `routine` and `tag` `manual`, `slot` empty, `title`, `routineName` (the template it came from, which names its book), `prompts` (from the template) with `lines` as the answers, or `text` for a blank page.
- Journal templates are data too: entries with id `template|<uuid>`, `routine` and `tag` `template`, `title` the name and `lines` the prompts (none means a blank page). They sync like any entry and are edited in the Manual journal. The web journal hides them.
- `tag` is the step's `run.tag` (`gratitude`, `win`, `script`, `action`, `review`, `note`), `run` for runs and `feel` for the "How did it feel?" answer, whose step is the literal `feel`.
- On the Mac: `KairosJournal.shared`, saved to `$ROOT/runner.json` (`{"entries": [...]}`) through `DataVault` as `runner` (snapshots, quarantine, recovery, git sync noun "journal note") and synced by `CloudSync` as document `runner`. Merging another copy is a union by id where the newer `updated` wins.
- Adding the `runner` document made `CloudSync` keep a list of known documents in `cloud-state.json`; when a new one appears it pulls everything once, so entries written before the Mac update still arrive.

## Mac app

- `AppSpec(id: "runner", name: "Ventus", symbol: "figure.mind.and.body", glyph: Glyphs.ventus (the eagle's head trailing into wind), hotKey: kVK_ANSI_2)`.
- **The window is where sessions run** (Pranav, 2026-11-19: the menu bar is only for glancing). `KairosWindow.shared.present(source:)` opens a 980×680 window (content min 880×620, frame autosave `runner.board`), hosted with `NSHostingView` (`sizingOptions = []`, so the content never pins the window size) and following `AppThemeStore.shared.publisher(for: "runner")`.
  - Left sidebar: Routine and Journal, then "Your routines": one card per routine with a guided step (`KairosStats`) showing days done, current streak and days skipped since it started, by Aqua's own day status (`ScheduleStore.status(on:in:)`), plus the best streak. While a session runs, the sidebar lists its steps with ticks, time spent or estimated, and click-to-jump.
  - Routine (`KairosToday`): chips for today and the next six days plus a calendar popover for any date, then the day's sessions as cards by morning and tonight. Done sessions are ticked, struck through and faded, with Look back. Open ones today have Start now (the next one is expanded with its steps, Return starts it). Every card has Preview.
  - Preview (`KairosPreview`): any session, any day, one step at a time with every beat listed (moves, reps, timers, rests, cues, lines, prompts). No timer runs and nothing is ticked.
  - Journal (`KairosJournalPage`), with a Dailies / Manual toggle. Dailies is a shelf of books, one per tag (`KairosShelf.kinds`: Gratitude, Wins, Scripts, Actions, Reviews, Runs, Notes), shown once a book has a page. A book (`KairosBookView`) is a two-page spread, one page per day (morning and night on the same page), flipped with the arrows or ← →, with Go to date. Manual is one book per template (the entry's `routineName` holds the template name, "Blank page" without one; one entry per page, oldest first, Edit on each page), New entry (`KairosNewEntry`: pick a template on the left, fill its prompts, ⌘S) and the templates row (New template, click one to edit).
  - A gear at the top right (⌘,) slides in a 260 pt settings sidebar on the right (`KairosSettings`) with the two toggles. Fixed-height stage screens sit in `kairosFill()`, a scroll view whose content is at least the visible height, so a short window scrolls instead of clipping.
- **The dropdown is a glance** (`KairosGlance`, 380×520, fixed): today's sessions with their status, a "Now" card with the current move and countdown while a session runs, an expand button and "Open Ventus". Nothing starts from it; every row opens the window. The right-click menu has Open Ventus, plus Pause and End session while running.
- Settings (right-hand sidebar from the gear): "Chime at each change" (`runner.sound`, default on) and "Wait for a click before each step" (`runner.hold`).
- While running, the menu bar shows the countdown and the move (`barTitle`).
- Run state is saved to UserDefaults `runner.run`, so a session survives a relaunch. `KairosRunner` ticks every 0.25 s and redraws the menu bar once a second.
- Keys: Return for Done, Said it and the primary button; Space pauses; ⌘Return for Save and next on writing and run screens.
- Chimes are `NSSound` Tink (step change) and Glass (finished).
- Colours: `KairosBoard` reads `AppThemeStore.shared.theme(for: "runner")` (Flint unless changed in Pocket Settings → Appearance).
- Log lines start with `kairos` (`kairos run started`, `kairos run finished`, `kairos journal saved`, …).
