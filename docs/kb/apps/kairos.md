# Ventus

Ventus (internal id `runner`) runs today's timed fitness routines step by step (mindfulness routines moved to Zenda on 2026-11-21, see [zenda.md](zenda.md)): press Start and it shows only what to do now, counts down, names each move and its reps, rests between rounds, and moves on by itself. Writing steps are typed into it and kept as a journal. Each finished step ticks the same `schedule.check` record Aqua uses, so Aqua on every device updates on its own. It was designed and built on 2026-11-19; it was briefly called Usanza, then Adesso.

It exists twice: on the Mac (`KairosApp.swift`, `KairosModel.swift`, ⌥2) and as the web app at `/Pocket/ventus/` (`web/ventus/`). Both read the same routines and write the same records.

Related: [schedule.md](schedule.md) (Aqua, where routines live and are edited), [../cloud-sync.md](../cloud-sync.md) (record kinds), [../web-pages.md](../web-pages.md) (the web app), [../theme.md](../theme.md) (app colours; Ventus defaults to Flint).

## Where the routine details live

Code holds only templates; every number lives in the database (Pranav, 2026-11-19), so changing a workout is a data change, never a code change. Each Aqua step may carry a `run` object next to `title` and `tip`, in the weekly `plan` and in `dated` lists alike:

| `type` | Fields | What Ventus does |
| --- | --- | --- |
| `tap` | none | Shows the step; Done moves on |
| `timed` | `seconds`, `cues[{at, text}]`, `quiet`, `reads`, `pick`, `every` | One countdown; the cue whose `at` (seconds in) has passed is shown as "Now"; `quiet` skips the chime at the end (body scan). `reads` is a pool of lines to read if picturing is hard: today's `pick` of them show one at a time, each for `every` seconds (default 20) |
| `box` | `seconds`, `pattern` (`[in, hold, out, hold]`, default 4-4-4-4), `cues` | Box breathing: a ball travels round a square (up on in, across on hold, down on out, back on hold) with the phase and its count in the middle |
| `moves` | `moves[{name, reps \| seconds, detail}]`, `seconds` (estimate) | One beat per move: `seconds` counts down, `reps` waits for Done |
| `intervals` | `rounds`, `on`, `off`, `names` (rotate), `unit`, `onLabel`, `offName` | Work and rest countdowns; the background turns warm on work and blue on rest |
| `rounds` | `rounds`, `unit` (`round` or `set`), `rest`, `moves` | Every move in order, then a rest that names the next round's first move |
| `log` | `plan`, `seconds` (estimate) | A data-entry screen: the plan, then time, distance and notes. Nothing is tracked (Pranav's call) |
| `say` | `lines`, `pool`, `pick`, `times`, `seconds` | One line at a time, "Said it" `times` times each. `lines` always show; `pool` adds today's `pick` of its lines |

Daily picks: a pool rotates by day, starting at `(dayNumber × pick) mod pool size` and taking `pick` lines in order (`dayNumber` is days since 1970-01-01 for the session's `yyyy-MM-dd`), so every line comes round before any repeats. `KairosPlan.pick` and `pick` in `plan.js` must stay identical.
| `write` | `fields` (lines; 0 or 1 means a paragraph), `tag`, `prompt`, `seconds` (a guide only) | Text saved to the journal as you type |

A step with no `run` uses "N min" in its title as a timer, otherwise it is a tap step. Only routines with at least one guided step (any type but `tap`) appear, so Hair care never does.

The Mac keeps `run` as loose JSON (`Loose` in `ScheduleModel.swift`), so it round-trips untouched through `schedule.json` and sync; the Aqua editor never changes it. A Mac build without `Loose` would strip `run` and push the routine back without it, so the Mac update must ship before `run` data is written.

The current data was generated by `run_for(title)` in `/mnt/project-files/kairos/runs.py` from the step titles and written with SQL. To change a workout, edit the routine's `run` objects in the `schedule.routine` record (or `schedule.json` on the Mac) and let sync carry it.

## Journal

- Record kind `runner.entry`, id `routine|day|slot|step` (the same shape as a check id). Data: `{id, routine, routineName, day, slot, step, title, tag, lines?, text?, seconds?, km?, notes?, feel?, updated}`.
- Manual entries: id `manual|<uuid>`, `routine` and `tag` `manual`, `slot` empty, `title`, `routineName` (the template it came from, which names its book), `prompts` (from the template) with `lines` as the answers, or `text` for a blank page.
- Journal templates are data too: entries with id `template|<uuid>`, `routine` and `tag` `template`, `title` the name and `lines` the prompts (none means a blank page). They sync like any entry and are edited in the Manual journal. The web journal hides them.
- `tag` is the step's `run.tag` (`gratitude`, `win`, `script`, `action`, `review`, `note`), `run` for runs and `feel` for the "How did it feel?" answer, whose step is the literal `feel`.
- Projects (2026-11-21): one per fitness routine, id `project|<routineId>`, `routine` the routine id, `tag` and `step` `project`, `slot` "", `title` the project name, `text` the goal, `day` the start date, `notes` the goal date, `lines` the targets, `feel` the achieved target indexes as a comma list ("0,1"; absent for none), `prompts` the milestones as `yyyy-MM-dd|Label`, `routineName`. Without one, the routine's name, `starts` and `ends` stand in. Never list it as writing.
- Workouts (2026-11-21): ad-hoc guided runs and logged workouts, id `workout|<uuid>`, `tag` `workout`, `routine` the project's routine id, `step` the kind (`run`, `rope`, `walk`, `gym`, `other`) or `guided`, `title`, `day`, `slot` "", `seconds`, `km` (run, walk), `text` the rope skip count as a string, `lines` `[sets]`, `feel` "1".."5", `notes`. They never tick Aqua. Never list them as writing either; anything that lists entries as journal pages filters out tags `project` and `workout`.
- On the Mac: `KairosJournal.shared`, saved to `$ROOT/runner.json` (`{"entries": [...]}`) through `DataVault` as `runner` (snapshots, quarantine, recovery, git sync noun "journal note") and synced by `CloudSync` as document `runner`. Merging another copy is a union by id where the newer `updated` wins.
- Adding the `runner` document made `CloudSync` keep a list of known documents in `cloud-state.json`; when a new one appears it pulls everything once, so entries written before the Mac update still arrive.

## Mac app

- `AppSpec(id: "runner", name: "Ventus", symbol: "figure.mind.and.body", glyph: Glyphs.ventus (three wind lines), hotKey: kVK_ANSI_2)`. Only Fitness routines show (`KairosFit.isFitness`: any step, weekly or dated, with `run.type` in moves, intervals, rounds or log); mindfulness and the journal pages belong to Zenda.
- **No dropdown** (Pranav, 2026-11-21). `KairosApp` overrides `toggle` and `show`, so a click on the menu-bar icon, ⌥2, a notification or `com.pranav.pocket.toggle` all call `openWindow`, which hides other dropdowns and runs `KairosWindow.shared.present(source:)`. The right-click menu keeps Open Ventus, plus Pause and End session while running, and the menu-bar title still shows the countdown and move (`barTitle`).
- **Window**: 1160×740 (content min 940×640, frame autosave `runner.board`), `NSHostingView` with `sizingOptions = []`, following `AppThemeStore.shared.publisher(for: "runner")`. A slim 88 pt left rail (`VentusRail`): the bear logo, then Today, Scheduled, Start and Review (⌘1–⌘4), each icon a SwiftUI `Path` on a 24 grid (`VentusGlyph`), and a gear (⌘,) with the two settings in a popover. Pages are in `VentusPages.swift`; shared colours and helpers in `Ventus`.
  - Today (`VentusTodayPage`): weekday and date, chips for days to the next milestone and the streak, one hero card per session today (day ring, project · n/total, session title, steps with icon, detail and minutes, Start · Nm or Resume), and on the side this week's dots, goal bars and the next session (dashed). Nothing today shows "Rest day" or "Nothing today".
  - Scheduled (`VentusScheduledPage`): project menu, Edit (the `VentusProjectEditor` sheet: name, goal, start, goal date, targets, milestones), the targets and a start-to-end timeline with milestones, a Monday-based week stepper, 7 day tiles and the chosen day's steps (interval on/off bars, rope set chips) with Preview and Start. Start on another day is an ad-hoc run.
  - Start (`VentusStartPage`): Guided tiles (today's session, one per distinct step name in the project, Any day) and Log tiles (Run, Rope, Walk, Gym, Other) that open `VentusLogSheet`.
  - Review (`VentusReviewPage`): project menu and Week / Project / All; days done, streak, hours moving, goals; heatmap; work minutes per session day; goal cards (click toggles achieved); feel trend; runs list.
  - Preview (`KairosPreview`): any session, one step at a time with every beat listed. No timer runs and nothing is ticked.
- **Run stage** (`KairosStage`) replaces the whole window while a run is live: a 260 pt steps list on the left (ticked, current with round n/N, remaining minutes, click to jump, elapsed time and bar) and the beat screen in the centre (`KairosRun`, big name and countdown, round dots, a blue chip for what's next, back / pause / skip, ✕ ends). The ground is warm while working and blue on rests. "‹ Day n" hides the stage without stopping the run; Today then offers Resume.
- **Projects** are `runner.entry` rows `project|<routineId>` (shape in the spec: title, text goal, day start, notes goal date, lines targets, feel achieved indexes, prompts `yyyy-MM-dd|Label`); `VentusProject` falls back to the routine's name and dates. **Workouts** are `workout|<uuid>` rows with tag `workout`, step `run`/`rope`/`walk`/`gym`/`other` from the Log sheet or `guided` from an ad-hoc run. Ad-hoc runs (`KairosRunState.adhoc`, and `only` for a single step) never tick Aqua and log their workout when finished. `KairosJournal.isDaily` excludes `project`, `workout`, `run`, `feel`, `manual` and `template`.
- Day status (`KairosDayState`): done, part, missed, open, future, and rest when every step's name is stretch, mobility, cool-down, recovery or rest. The streak counts done days back from today; today, rest days and empty days do not break it. Same rules as `web/ventus/projects.js`.
- Settings: "Chime at each change" (`runner.sound`, default on) and "Wait for a click before each step" (`runner.hold`).
- Run state is saved to UserDefaults `runner.run`, so a session survives a relaunch. `KairosRunner` ticks every 0.25 s and redraws the menu bar once a second.
- Keys: Return for Start, Done, Said it and the primary button; Space pauses; ⌘Return for Save and next and for Save in the Log sheet; ⌘S saves the project editor.
- Chimes are `NSSound` Tink (step change) and Glass (finished).
- Logo: `Sources/Pocket/Resources/ventus-bear.png` (256 px), an SPM resource. `VentusArt` looks for `Pocket_Pocket.bundle` in the app's Resources, next to the executable, then in the source checkout's `.build/release`, and falls back to a paw symbol.
- Colours: `KairosBoard` reads `AppThemeStore.shared.theme(for: "runner")`, Umber (brown on beige) unless changed in Pocket Settings → Appearance. Hot `#C0622F` and rest `#6F97B3` are fixed.
- Log lines start with `kairos` (`kairos run started`, `kairos step run started`, `kairos workout logged`, `kairos project saved`, `kairos tab`, …).

## Web app

Rebuilt on 2026-11-21 as a fitness app (mindfulness moves to Zenda): see [../web-pages.md](../web-pages.md#ventus-webventus) for the screens. In short:
- Only fitness routines appear (any step with `run.type` `moves`, `intervals`, `rounds` or `log`), each as a project whose details come from its `project|<routineId>` entry.
- Four tabs in a bottom bar: Today (week dots, session hero with Start, goal bars, next session), Scheduled (project pill and editor sheet, targets and timeline, week stepper, day rows, a Day screen with Preview and Start), Start (guided tiles per step, Any day, and Log tiles opening the Log sheet) and Review (stats, heatmap, minutes chart, goal bars that toggle achieved, feel trend, runs; the gear opens Settings).
- Same engine (`web/ventus/plan.js`), same run screens restyled to the browns and beiges palette (warm while working, blue on rests). Scheduled sessions tick `schedule.check`; ad-hoc runs (a single step, or a day that isn't today) carry `adhoc: true` and their steps in the run state, tick nothing and save a `workout` entry on finish.
- The Journal view is gone; run logs, feel answers and workouts show in Review.
- Bear icon (`icon-192.png`, `icon-512.png`, `icon.svg` embedding a 256 px copy) cut from the R2 bear (back turning into wind) in `/mnt/project-files/eighth-app/final-logos/ventus.png`; the Mac copy is `Resources/ventus-bear.png`. Runner state is kept in `localStorage` `runner.run.v1`; the chosen project in `runner.project`.
