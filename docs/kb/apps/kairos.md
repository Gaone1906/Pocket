# Kairos

Kairos (internal id `runner`) runs today's timed routines step by step: press Start and it shows only what to do now, counts down, names each move and its reps, rests between rounds, and moves on by itself. Writing steps are typed into it and kept as a journal. Each finished step ticks the same `schedule.check` record Orario uses, so Orario on every device updates on its own. It was designed and built on 2026-11-19; it was briefly called Usanza, then Adesso.

It exists twice: on the Mac (`KairosApp.swift`, `KairosModel.swift`, ⌥K) and as the web app at `/Pocket/kairos/` (`web/kairos/`). Both read the same routines and write the same records.

Related: [schedule.md](schedule.md) (Orario, where routines live and are edited), [../cloud-sync.md](../cloud-sync.md) (record kinds), [../web-pages.md](../web-pages.md) (the web app), [../theme.md](../theme.md) (app colours; Kairos defaults to Apricot).

## Where the routine details live

Code holds only templates; every number lives in the database (Pranav, 2026-11-19), so changing a workout is a data change, never a code change. Each Orario step may carry a `run` object next to `title` and `tip`, in the weekly `plan` and in `dated` lists alike:

| `type` | Fields | What Kairos does |
| --- | --- | --- |
| `tap` | none | Shows the step; Done moves on |
| `timed` | `seconds`, `cues[{at, text}]`, `quiet` | One countdown; the cue whose `at` (seconds in) has passed is shown as "Now"; `quiet` skips the chime at the end (body scan) |
| `moves` | `moves[{name, reps \| seconds, detail}]`, `seconds` (estimate) | One beat per move: `seconds` counts down, `reps` waits for Done |
| `intervals` | `rounds`, `on`, `off`, `names` (rotate), `unit`, `onLabel`, `offName` | Work and rest countdowns; the background turns warm on work and blue on rest |
| `rounds` | `rounds`, `unit` (`round` or `set`), `rest`, `moves` | Every move in order, then a rest that names the next round's first move |
| `log` | `plan`, `seconds` (estimate) | A data-entry screen: the plan, then time, distance and notes. Nothing is tracked (Pranav's call) |
| `say` | `lines`, `times`, `seconds` | One line at a time, "Said it" `times` times each |
| `write` | `fields` (lines; 0 or 1 means a paragraph), `tag`, `prompt`, `seconds` (a guide only) | Text saved to the journal as you type |

A step with no `run` uses "N min" in its title as a timer, otherwise it is a tap step. Only routines with at least one guided step (any type but `tap`) appear, so Hair care never does.

The Mac keeps `run` as loose JSON (`Loose` in `ScheduleModel.swift`), so it round-trips untouched through `schedule.json` and sync; the Orario editor never changes it. A Mac build without `Loose` would strip `run` and push the routine back without it, so the Mac update must ship before `run` data is written.

The current data was generated by `run_for(title)` in `/mnt/project-files/kairos/runs.py` from the step titles and written with SQL. To change a workout, edit the routine's `run` objects in the `schedule.routine` record (or `schedule.json` on the Mac) and let sync carry it.

## Journal

- Record kind `runner.entry`, id `routine|day|slot|step` (the same shape as a check id). Data: `{id, routine, routineName, day, slot, step, title, tag, lines?, text?, seconds?, km?, notes?, feel?, updated}`.
- `tag` is the step's `run.tag` (`gratitude`, `win`, `script`, `action`, `review`, `note`), `run` for runs and `feel` for the "How did it feel?" answer, whose step is the literal `feel`.
- On the Mac: `KairosJournal.shared`, saved to `$ROOT/runner.json` (`{"entries": [...]}`) through `DataVault` as `runner` (snapshots, quarantine, recovery, git sync noun "journal note") and synced by `CloudSync` as document `runner`. Merging another copy is a union by id where the newer `updated` wins.
- Adding the `runner` document made `CloudSync` keep a list of known documents in `cloud-state.json`; when a new one appears it pulls everything once, so entries written before the Mac update still arrive.

## Mac app

- `AppSpec(id: "runner", name: "Kairos", symbol: "figure.mind.and.body", glyph: Glyphs.kairos (balanced stones), hotKey: kVK_ANSI_K)`.
- **The window is where sessions run** (Pranav, 2026-11-19: the menu bar is only for glancing). `KairosWindow.shared.present(source:)` opens a 980×680 window (content min 820×620, frame autosave `runner.board`), hosted with `NSHostingView` (`sizingOptions = []`, so the content never pins the window size) and following `AppThemeStore.shared.publisher(for: "runner")`. On the left, a sidebar shows today's morning and tonight sessions with Start or Continue. While a session runs, the sidebar instead lists its steps with ticks, time spent or estimated, and click-to-jump. At the bottom are Today and Journal and the two settings toggles. On the right is the stage: "Up next" (the next unfinished session with each step and how it runs, and a big Start), the running step, the finished screen or the journal. Fixed-height stage screens (Up next, countdowns, rests, reps, waiting, run log) sit in `kairosFill()`, a scroll view whose content is at least the visible height, so a short window scrolls instead of clipping the Done button.
- **The dropdown is a glance** (`KairosGlance`, 380×520, fixed): today's sessions with their status, a "Now" card with the current move and countdown while a session runs, an expand button and "Open Kairos". Nothing starts from it; every row opens the window. The right-click menu has Open Kairos, plus Pause and End session while running.
- Settings: "Chime at each change" (`runner.sound`, default on) and "Wait for a click before each step" (`runner.hold`).
- While running, the menu bar shows the countdown and the move (`barTitle`).
- Run state is saved to UserDefaults `runner.run`, so a session survives a relaunch. `KairosRunner` ticks every 0.25 s and redraws the menu bar once a second.
- Keys: Return for Done, Said it and the primary button; Space pauses; ⌘Return for Save and next on writing and run screens.
- Chimes are `NSSound` Tink (step change) and Glass (finished).
- Colours: `KairosBoard` reads `AppThemeStore.shared.theme(for: "runner")` (Apricot unless changed in Pocket Settings → Appearance).
- Log lines start with `kairos` (`kairos run started`, `kairos run finished`, `kairos journal saved`, …).
